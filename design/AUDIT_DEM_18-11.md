## Not sure

- **End-to-end timing between `hub` `DesktopBridge` and `desktop-mcp` `StateBridge` on a real task (`FIELD_REPORT.md:73`):** Both sides implement the `task_active.json`, `input_lock.json`, `indicator.json`, `RELEASE`, `owner_took_over.json`, and `screen_view.json` file contract and pass isolated unit tests, but without running commands we could not verify whether file-polling races occur under real load when both processes poll the same directory concurrently.
- **Vietnamese IME (UniKey/EVKey) key-transformation behavior (`desktop-mcp/FIELD_REPORT.md:18,93`):** `Desktop._type_real` (`desktop-mcp/src/turbo_desktop/engine.py:1207-1227`) detects length/content mismatches after typing via `ValuePattern` read-back, but whether UniKey transforms `SendKeys` events in fields without `ValuePattern` (such as rich editors or Explorer rename boxes) cannot be confirmed from code inspection alone.
- **Multi-monitor DPI scaling for real-input clicks (`FIELD_TASKS.md:63`, `desktop-mcp/FIELD_REPORT.md:51`):** `border.set_per_monitor_dpi_aware()` (`desktop-mcp/src/turbo_desktop/border.py:205`) enables `PER_MONITOR_AWARE_V2` at server startup, but coordinate accuracy across monitors with mixed DPI scales could not be verified without a multi-monitor test run.
